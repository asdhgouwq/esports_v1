dol.gg — Date of Legends / Mac 인수인계
작성: 2026-10-17 (한국 시간) / 최신 변경 사항은 문서 끝의 후속 작업 참고

1. 프로젝트와 현재 방향
- LoL e스포츠 정보 사이트. gol.gg의 경기/통계 탐색 기능을 참고한다.
- 최종 브랜드는 소문자 dol.gg, 전체 이름 Date of Legends.
- 실제 개발 대상은 frontend/ (React/Vite/Tailwind)와 backend/ (Express/Supabase).
- 루트 index.html, src/는 이전 정적 사이트다. 기존 README와 ARCHITECTURE도 이전 구조 중심이라 실제 코드와 다르다.
- e-signature는 잘못 지정했던 별도 프로젝트다. 작업 대상으로 삼지 않는다.

2. 사용자와 확정한 화면 구성
- 메인: 카드 대신 작은 한 줄 메뉴: 전체 경기, LCK, LPL, LEC, WORLDS, MSI, FST.
- 메뉴를 누르면 각각 독립 페이지로 이동한다. 메인 필터로만 처리하지 않는다.
- 리그: /leagues/lck, /leagues/lpl, /leagues/lec
- 국제 대회: /tournaments/worlds, /tournaments/msi, /tournaments/fst
- 메인은 리그 무관 최근 진행된 경기 최신순 목록. 날짜(KST), 리그/대회, 양 팀, 시리즈 스코어를 표시한다.
- /match/:gameId 상세 화면은 Preview(경기 전), 1세트, 2세트, 3세트, 4세트, 5세트, 요약의 7개 탭.
- Preview에는 로스터/최근 경기 및 상대 전적/관전 포인트 영역을 배치했다. 현재 내용은 데이터 연결 대기 안내다.
- 세트에는 승리 팀/시간/패치/픽밴/선수 기록 영역, 요약에는 수집된 세트의 합산 스코어와 결과 목록.
- 기록 없는 세트에 경기 취소나 종료를 단정하지 않고 안내 문구를 표시한다.
- /match/layout-preview 는 기본적으로 빈 기록의 레이아웃을 보는 주소다. 세트 탭의 '예시 밴픽 보기'를 켜면 별도로 표시된 가상 조합을 볼 수 있으며 실제 경기/DB 데이터는 아니다.

3. 현재 구현과 검증
- 프런트엔드 빌드가 Windows Node v24.18.1에서 통과했다. Mac에서는 별도 설치와 빌드 확인이 필요하다.
- Tailwind 4용 @tailwindcss/postcss 설정 수정 완료.
- 메인 시리즈 집계: match_id 기준, 팀 진영 변경을 팀 이름으로 추적, 중복 game_id 제외, 승패 없는 경기 제외.
- API GET /api/matches?limit=200&expand_series=true 는 초기 조회 경기와 같은 match_id의 세트들을 추가 조회한다.
- 집계 로직은 진영 변경/중복 제거/리그 무관 정렬/KST 날짜를 로컬 픽스처로 검사했다. API 확장도 모의 DB로 검사했다.
- 리그 분류/전용 페이지 이동/새로고침/상세 탭 전환/키보드 이동을 브라우저로 확인했다.
- 마지막 실제 Supabase 조회는 성공 응답, 경기 0건이었다. 운영용 데이터 수집/완성된 선수 기록 검증은 아직 안 됐다.

4. 남은 작업과 알려진 한계
- 실제 경기 및 선수 통계 수집/DB 스키마/정합성을 확인하고 연결해야 한다.
- 리그 전용 페이지는 전체 최근 200세트에서 해당 리그를 골라낸다. API 서버에서 리그별 조회를 지원하도록 개선할 필요가 있다.
- 상세 페이지도 최근 조회 결과에서 gameId를 찾는다. 오래된 경기 직접 접속용 단일 경기/시리즈 API가 필요하다.
- 세트 번호는 수집된 경기의 시간순이다. 누락 세트가 있으면 정확한 번호가 보장되지 않으므로 원본 세트 번호 연결이 필요하다.
- 기존 DB의 player_stats에는 team 열이 없다. 새 수집은 원본 Team을 검증하고, API/AI에서는 같은 경기의 최종 픽 10개가 모두 고유한 경우에만 챔피언으로 팀을 연결한다. 불명확하면 팀을 지정하지 않는다.
- 동기화의 실패 전달과 실제 저장 건수 검증은 후속 작업에서 수정했다.
- backend와 frontend의 npm test가 구현되어 있다. 최신 결과는 후속 작업 참고.
- 배포나 GitHub 업로드는 하지 않았다. frontend/와 backend/는 기존 Git에서 아직 untracked 상태였다.
- 이 ZIP에는 작업 디렉터리의 미커밋 파일도 포함하지만 .git 이력, .env 값, node_modules, dist, 대화 원문은 없다.

5. Mac에서 실행
- Node 24 계열 설치. 현재 Vite의 요구 버전은 ^20.19.0 또는 >=22.12.0이다.
- ZIP을 풀고 esports_v1 폴더를 Codex의 로컬 프로젝트로 연다.
- backend/.env.example을 참고해 backend/.env를 준비한다.
  SUPABASE_URL, SUPABASE_ANON_KEY, PORT=3000
- 원래 PC의 backend/.env와 frontend/.env가 필요하면 사용자 본인이 별도 비공개 경로로 옮긴다.
- frontend/.env.example에는 값 없는 템플릿만 포함했다. VITE_API_URL 기본값은 http://localhost:3000.
- Supabase의 같은 프로젝트에 연결하면 클라우드 DB는 그대로 사용한다. ZIP에 DB 덤프는 없다.
- 터미널 1 (esports_v1 폴더 기준):
  cd backend
  npm ci
  npm start
- 터미널 2 (esports_v1 폴더 기준):
  cd frontend
  npm ci
  npm run dev -- --host 127.0.0.1
- 브라우저: http://127.0.0.1:5173/
- 상세 구조: http://127.0.0.1:5173/match/layout-preview
- 빌드 확인 (frontend 폴더에서): npm run build
- 이전 Windows의 localhost 서버는 Mac으로 이전되지 않는다. Mac에서 다시 실행해야 한다.

8. Mac 후속 작업 (2026-10-19)
- 제품의 핵심 목적은 AI가 경기 내용을 쉽게 요약해 제공하는 것이다.
- 요약 탭의 AI 경기 총평과 각 1~5세트의 AI 요약 화면/서버 연결을 구현했다.
- 한줄 요약, 핵심 포인트, 양 팀 평가를 공통으로 제공한다. 직접 작성란은 '내 메모'로 접어서 유지한다.
- backend/src/services/aiSummary.js는 서버 DB 기록을 조회하고 OpenAI Responses API의 구조화 출력으로 요약한다.
- 처음에는 별도 OpenAI API 키 방식으로 준비했으며, 이후 아래 9번의 ChatGPT 구독 연동으로 기본값을 변경했다.
- 실제 AI 연결 확인은 아래 9번의 최신 상태를 참고한다.
- Supabase 연결은 완료했으나 현재 키로 조회되는 경기 기록은 0건이다. 빈 DB/RLS 여부는 미확인이다.
- 요약은 경기/선수 기록과 모델/프롬프트 버전 해시 기준으로 backend/.cache/ai-summaries/에 저장한다. Git 제외.
- 동일 요약 생성은 묶어서 처리하고 동시 2건/분당 10건으로 제한한다.
- 한타/골드 타임라인은 미수집이므로 구체적인 승부처를 추측하지 않도록 지시한다.
- backend npm test (AI 서비스/HTTP 9개), frontend npm test (집계 5개), frontend npm run build 통과.
- 별도 로컬 모의 응답으로 전체 총평, 두 세트의 자동 생성과 표시를 확인했다. 실제 생성 품질은 키/경기 데이터 연결 후 확인한다.
- 이 변경은 맥북 로컬에 반영되어 있으며 별도 GitHub 푸시/배포는 수행하지 않았다.

9. ChatGPT Pro 구독 연동 (2026-10-19)
- 사용자 요청에 따라 공식 Sign in with ChatGPT의 로컬 개인용 앱 흐름을 구현했다.
- 기본 AI_AUTH_MODE=chatgpt. API 키 결제로 자동 전환하지 않는다. 별도 API 키는 필요 없다.
- 요약/각 세트의 AI 카드에서 Continue with ChatGPT 버튼으로 로그인과 구독 사용 승인을 진행한다.
- 실제 공식 OAuth 콜백 성공 후 화면의 '구독 연결됨'과 계정별 모델 카탈로그를 확인했다.
- 모델은 계정의 /v1/models 카탈로그에서 visibility=list인 항목만 선택하며 이름을 고정하지 않는다.
- backend/src/services/chatgptAuth.js: PKCE/state/nonce, JWT 서명/발급자/대상/만료 검증, 계정별 등록/갱신/해제.
- backend/.local/chatgpt-auth/accounts.json에 기기별 등록과 계정별 토큰을 저장한다. 폴더 700/파일 600, Git 제외.
- 토큰을 채팅/로그/GitHub/프런트엔드 저장소에 노출하지 않는다. Codex의 인증 정보와 별개다.
- backend/src/api/chatgptRoutes.js는 루프백 Host/Origin/JSON 요청을 검사한다. 서버도 127.0.0.1에만 바인딩한다.
- 콜백은 http://127.0.0.1:3000/auth/callback. 프런트엔드 http://127.0.0.1:5173. 외부 공개 서버용 인증은 아니다.
- 구독 추론은 OAuth Bearer로 Responses API에 store=false/stream=true/input 배열을 전송하고 response.completed 이후에만 표시한다.
- 구독 사용 한도/중단 상태를 별도로 표시한다. 캐시는 계정/모델/기록별로 분리한다.
- 연결 해제는 갱신 토큰 원격 폐기를 재시도하고 로컬 사용은 해제한다. 원격 확인 실패는 화면에 안내한다.
- 서버 테스트 21개, 프런트엔드 테스트 5개, 프런트엔드 빌드 통과.
- 실제 ChatGPT 구독으로 검증용 가상 경기의 요약 생성 성공(billing=chatgpt_plan). DB에 가상 기록을 넣지 않았다.
- store=false에서 최종 response.completed의 output이 비어 있을 수 있어 output_item.done을 합치되 최종 완료 이벤트 이후에만 표시한다.
- 서버 재시작과 화면 새로고침 후에도 구독 연결과 계정별 모델 7개 조회가 유지됨을 확인했다.
- 재로그인 URL은 일회용 로컬 티켓을 거쳐 서버에서 공식 인증 주소로 이동한다. id_token_hint를 프런트엔드 응답에 넣지 않는다.
- 공식 문서: https://developers.openai.com/siwc/token-sharing-open-source/sign-in
- 이 기능은 맥북의 개인용 로컬 실행 기준이다. 공개 서비스의 모든 사용자에게 Pro 구독을 공유하는 방식이 아니다.

10. 세트별 토너먼트 드래프트 보기 (2026-10-19)
- 세트 탭의 기존 작은 픽/밴 이미지 줄을 TournamentDraft 컴포넌트로 교체했다.
- 블루·레드 팀을 마주 배치하고 팀별 5밴/5픽, 금지 표시, 챔피언 한글 이름/초상화와 최종 조합을 보여준다.
- 밴픽을 세트 상단에 배치했으며 기존 AI 요약과 선수 기록은 이어서 제공한다.
- DDragonContext에서 공식 ko_KR 챔피언 메타데이터를 조회하고 별칭을 실제 이미지 ID에 대응한다.
- 선수 이름/포지션은 game_id와 명시된 team, 챔피언이 일치하는 단일 기록만 연결한다. 팀이 없는 선수나 이전 세트 기록을 추정 배정하지 않는다.
- 5명의 서로 다른 포지션이 모두 확인되면 포지션순으로 정렬한다. 그 외에는 목록을 유지한다. 실제 선택 순서는 미수집이므로 드래프트 타임라인을 만들지 않는다.
- 빈 슬롯/일부 누락을 그대로 표시하며 이미지 로딩 실패 시 텍스트 대체 표시를 제공한다.
- layout-preview에서만 '예시 밴픽 보기' 버튼을 제공한다. 화면 예시 배너를 표시하고 DB나 AI 생성에는 연결하지 않는다.
- 프런트엔드 테스트 9개/빌드 통과. 실제 브라우저 611px 너비에서 10픽/10밴, 초상화 20개 로딩, 가로 넘침 없음, 세트 전환 후 빈 상태 초기화를 확인했다.
- Riot Data Dragon 문서: https://developer.riotgames.com/docs/lol#data-dragon

11. 첨부 이미지 기준 밴픽 순서 표시 (2026-10-19)
- 세로 조합 카드를 팀별 Bans/Picks 두 줄의 원형 초상화로 바꿨다. 넓은 화면은 양 팀 좌우 배치, 좁은 화면은 팀별 위아래 배치다.
- 밴 3|2, 선픽 팀 픽 1|2|2, 후픽 팀 픽 2|2|1 구분선을 넣었다. 확인된 선픽에만 1st를 표시하며 전체 픽 순서는 툴팁으로 제공한다.
- 전체 픽 번호: 선픽 팀 [1,4,5,8,9], 후픽 팀 [2,3,6,7,10]. 실제 블루·레드 진영과 독립적으로 계산하며 포지션순으로 다시 정렬하지 않는다.
- GET /api/matches/:gameId/draft는 DB에서 실제 경기 존재를 확인한 후 Leaguepedia PicksAndBansS7의 Team1/2Pick1~5, Ban1~5를 조회한다. GameId/양 팀/완전한 최종 픽 구성을 검증하고 반환한다.
- DB 스키마 변경이나 데이터 쓰기 없이 조회 결과를 메모리에 캐시한다. 동일 요청 중복 제거, 동시 조회 2개 제한, 원본 요청 제한 시 10분 대기를 적용한다.
- 원본 순서가 없거나 조회 실패 시 최종 목록으로 돌아가고 선픽·픽 번호·순서 구분선은 붙이지 않는다. 빈 상태는 자리만 표시한다.
- 외부 실제 조회는 현재 ratelimited 응답이어서 실제 경기의 원본 순서 연동 검증은 남아 있다. 원본 스키마는 Leaguepedia Cargo 선언 문서로 확인했다.
- 로컬 가상 경기로 순서 API→hook→화면 경로를 검증했다. 저장된 역할순 첫 챔피언(오른) 대신 원본 선픽(오공)이 표시되고, 다음 세트에 순서가 없으면 선픽/번호가 제거되는 것을 확인했다.
